# homework-V2 · 产品方案

## 1. 定位与目标用户

**定位**：面向 6-9 年级学生**家长**的 AI 家教——优先把题目讲透，批改是附带价值。

**用户**：家长（使用者）、孩子（受益者）。**不含**老师角色。

**一句话价值主张**：拍张作业图，AI 把每道题的**解题思路和答案**讲给你，孩子的作答能核对就核对，错题自动沉淀成错题本。

## 2. V1 范围（本版本上线目标）

| 维度 | V1 |
|---|---|
| 学科 | **数学**（6-9 年级） |
| 入口 | 微信（经 OpenClaw 插件转发） |
| 输出 | 局域网 HTML 页（Next.js）· 微信回推签名短链 |
| 模型 | **订阅模式**（本机已登录的 Claude Code CLI + Codex CLI），不使用 API Key |
| 本地模型 | V1 **不启用**（Feature Flag `LOCAL_VLM_ENABLED=false`） |
| 绑定 | 1 个微信 openId = 1 个孩子；每孩子一个 `parent_token` 做 cookie 鉴权 |
| 错题本 | 按**知识点 + 日期**归类；采用自包含快照，与作业生命周期解耦 |
| 教材章节上传 | **V2 再加**，V1 不做 |

### 2.1 数学题型支持度（V1）

| 类别 | 支持度 | 说明 |
|---|---|---|
| 计算题、解方程、不等式 | 必须支持 | SymPy 等价判定稳定 |
| 填空题（数值/表达式） | 必须支持 | 同上 |
| 选择题 | 必须支持 | 答案为字母，字符串匹配 |
| 代数 / 函数分析 / 二次函数 | 必须支持 | 解析型步骤 + 端点验证 |
| 应用题（一元/二元方程建模） | 必须支持 | 生成方程后 SymPy 求解 |
| **几何计算**（求长度/面积/角度） | 尽力而为 | VLM 读图不稳时降为「未批改」只展示解法 |
| **几何证明** | **非目标** | 步骤正确性无法机器验证，不承诺 |
| **作图题 / 尺规作图** | **非目标** | 输出无图形可判定 |
| **开放性/探究性/写说明** | **非目标** | 无标准答案可比对 |

对「非目标」题型，`verdict` 恒为 `unmarked`，页面提示"此类题目仅供参考"。

## 3. 核心产品理念

### 3.1 "读准题 > 批准答"

传统方案把精力放在"判学生答案对错"，本产品翻转优先级：**先让 AI 把印刷题读准、把图表理解准、把解题过程讲清**。学生答案只是副产品。

原因：
- 读题是上游，读错了下游一切崩盘
- 家长真正需要的是**辅导能力**，不是判分器
- 判分误判会让家长失去信任，"能批就批、不能批就跳"体验反而更好

### 3.2 "能批就批，不能批就不批"（二态 + 跳过）

对每道题：
- ✓ **正确**：高置信确认学生答案与 AI 答案一致
- ✗ **错误**：高置信判学生答案错 + 给出订正
- — **未批改**：学生答案模糊/无法定位/AI 不确定，不强判，只展示解答

**不设"⚠ 待确认"**——家长没有复核义务，含糊态只会造成决策负担。

### 3.3 所有题都生成讲解

无论对错，每道题都输出"解题思路 + 最终答案"。这是产品**差异化的核心**——它是 AI 家教，不是判分器。

## 4. 用户流程

```
[家长] 微信发送作业图
   ↓
[系统] 回复"正在批改中，约 30 秒..."
   ↓
[家长] 收到签名短链 http://<内网IP>:3100/r/{shortId}?t=<parent_token>&e=<expSec>&s=<HMAC>
   ↓                              （三件套必须同时存在，15 分钟内有效，详见 §8.1）
[家长] 打开链接 → 服务端校验签名/过期 → 写入 30 天 cookie → 看到大题-小题层级的讲解页
   ↓
[家长] 对错题点"加入错题本"（或默认自动加入）
   ↓
[家长] 稍后访问错题本页，按知识点复习
```

### 5.2 错题本页 `/mistakes`

- 默认按**时间轴**展示
- 筛选：知识点、日期范围、对错状态
- 每条错题：题目截图 + AI 解答 + 加入时间 + 知识点标签

基于错题本的知识点分布生成变式题包。V1 仅占位路由。

## 6. 判定规则（仅 V1 数学，二态 + 跳过）

| 条件 | 结果 |
|---|---|
| AI 自解 + SymPy 验证**一致** & 学生答案**可识别** & 匹配 | ✓ 正确 |
| AI 自解 + SymPy 验证**一致** & 学生答案**可识别** & 不匹配 | ✗ 错误 |
| AI 自解 + SymPy **不一致** | — 未批改（只展示解答，不下判定） |
| 学生答案**无法识别** | — 未批改 |
| 图像模糊/截断/题面识别失败 | — 未批改，提示重新拍 |

## 7. 错题本归类

### 7.1 标签维度（V1）

- **知识点**（`knowledge_tag`）：来自内置 K12 数学知识点树（~300 节点，6-9 年级）
- **日期**（`created_at`）：自动
- **错因**（`error_type`，可选）：概念不清 / 计算失误 / 漏解 / 题意理解偏差（LLM 生成时结构化输出）

### 7.2 视图

- 时间轴视图：按日期倒序
- 知识点视图：按知识点分组聚合
- 薄弱点 Top 5：近 30 天**错题出现最多**的知识点（按错题计数 + 占比）

> 注：V1 不做"错误率"指标。错题本数据集只有错题样本、没有"总做题数"，算不出真正的错误率；硬算会误导家长。需要错误率须等到 V2 引入逐题历史后再做。

## 8. 数据与隐私

- 图片、批改结果**只存本地**（WSL 本机 SQLite + 本地文件系统）
- 不上云，不共享
- 家长可随时删除某份作业 / 清空错题本
- **错题本独立于作业**：删除作业不会删除已加入错题本的条目；错题本图片另存一份快照

### 8.1 访问控制

**机制**：

- 微信回推短链三件套 `?t=<parent_token>&e=<expSec>&s=<HMAC>`，缺一即拒
- 首次打开后 → 校验签名 + 未过期 → 写入 httpOnly cookie（`hw_parent`，30 天）→ 302 到干净 URL
- 后续 30 天内本机浏览器直接访问，不再需要短链
- 每个 cookie 反查到唯一 `child_id`；跨 child 访问一律拒绝

**威胁模型（诚实版）**：

V1 短链**本质是 bearer 凭据**——谁在 15 分钟签名窗口内拿到完整的 `?t=&e=&s=` URL，谁就能首次进入并在本机种下 30 天 cookie。HMAC 只能防两件事：

- ✅ 防**篡改**：别人不能把合法短链里的 `shortId` 改成另一个 child 的
- ✅ 防**枚举**：别人不能凭空猜出一个合法 `parent_token`

HMAC **不能防**：

- ❌ 家长**主动转发**链接给第三方（微信群、截图等）
- ❌ 15 分钟窗口内的**截屏/录屏泄漏**
- ❌ 同一链接在窗口内被**重放**（没做 nonce）

V1 选择接受这些残余风险，基于以下前提缓解：

1. **部署范围**：仅局域网访问，攻击者需先接入家庭 Wi-Fi
2. **短窗口**：签名 URL 仅 15 分钟内有效（`SHORT_LINK_TTL_MINUTES`），窗口后即失效
3. **后续门槛**：cookie 只在**首次进入的那台设备**生效，转发链接给第三方后对方也需在 15 分钟内打开并"占位"
4. **单 child 绑定**：即使泄漏，暴露面也限于该孩子一份作业/错题，不会扩散到其他用户

**V1.1 计划**：把短链改成**一次性 code**——访问后立即失效，再签发一次性 cookie 交换码。届时即可关闭"短链 = bearer"这个口。

- 无 cookie / cookie 失效 / 签名错 / 过期 → 跳 `/auth-required?reason=<...>` 提示页，要求从微信重新进入

## 9. 非目标（明确不做）

- 老师/机构端
- 答案库/题库采买
- 作业打印/下发
- 社交/排行榜
- V1 不做语文作文/阅读、英语作文（AI 能力边界，不承诺）
- V1 不做几何证明、尺规作图、开放性探究题（见 §2.1）
- V1 不做多孩子支持、跨设备同步、cookie 轮换

## 10. 成功指标（V1 验收）

| 指标 | 目标 |
|---|---|
| 端到端批改耗时（20 题数学） | P50 ≤ 45s · P90 ≤ 60s |
| 题面识别准确率（含简单图表，V1 支持题型范围内） | ≥ 90% |
| 自解题答案正确率（V1 支持题型范围内，与人工校对） | ≥ 88% |
| 学生答案识别覆盖率 | ≥ 60%（剩余标为"未批改"） |
| 家长"批改有误"反馈率 | ≤ 10% |
| 「非目标」题型误判率（不应出现 ✓/✗） | 0 |

**不再设置 "每份作业成本" 指标**：V1 订阅模式下 LLM 费用为月度固定支出，按次量化没有意义。
运维成本在产品文档层面以"订阅月费 + 电费"粗估，不写入验收。
